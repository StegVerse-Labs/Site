Interlock / InTr Connections

A response packet starts the connection-initiation sequence. It does not self-authorize the connection.

The reusable pattern

1. Response packet submitted
The exact source-owned response or artifact is retained and hash-bound.
2. Receiving adapter validates the packet
The adapter checks the expected request, response class, profile, and exact payload identity.
3. Registered Node stages Universal InTr
The adapter binds the packet to the local registered StegOS Node / Interlock and the existing stegverse.universal-intr-transport/v1 and stegverse.universal-intr-materialization-request/v1 schemas.
4. Submission initiates the connection attempt
A write-once Node outbox entry is triggered toward an installed/advertised InTr profile.
5. Ingress admission is retained
INGRESS_ADMITTED is shown only after an authentic ingress receipt validates against the exact request.
6. Connection established only after downstream evidence
The receiving profile must produce its required authentic receiver/relationship receipt before Site reports CONNECTION_ESTABLISHED.

Connection state vocabulary

WAITING_FOR_RESPONSE_PACKET

No response retained yet.

PACKET_ACCEPTED

Exact packet/artifact retained and hash-bound.

OUTBOX_STAGED

Canonical request persisted to the registered Node outbox.

CONNECTION_INITIATED

Materialization trigger emitted to the selected InTr ingress.

INGRESS_ADMITTED

Transport ingress accepted the exact request. This is not downstream execution.

AWAITING_DOWNSTREAM_RECEIPT

Ingress admitted; receiver completion is not yet proven.

CONNECTION_ESTABLISHED

Profile-required downstream/relationship evidence has been retained and validated.

BLOCKED_PROFILE_UNAVAILABLE / FAIL_CLOSED

The requested profile is unavailable or a binding check failed.

Preflight a response packet

The generic documentation surface can inspect the response-packet handoff metadata and determine whether its requested profile is currently advertised. The profile-specific adapter—not this documentation page—owns Node-outbox staging and actual InTr initiation.

HIL is the working reference

HIL already implements this sequence: participant response PDF → exact hash/provenance → Universal InTr intent → materialization request → registered Node outbox → InTr trigger → ingress receipt. The general connection contract reuses that pattern rather than defining a second transport.
