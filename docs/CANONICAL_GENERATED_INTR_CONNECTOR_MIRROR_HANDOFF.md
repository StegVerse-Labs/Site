
The checked-in manifest binds the artifact, registry, and each selected profile by SHA-256. The offline verifier recomputes the artifact hash and rejects any PyPI, CDN, GitHub-runtime, or third-party package authority flag.

## Canonical profile consumers

| Site lane | Canonical profile | Operation | Consumer behavior |
| --- | --- | --- | --- |
| Evaluator review | `evaluator-read-review` | `READ_REVIEW` | Builds the deterministic canonical intent before the existing request/receipt projection. |
| HIL submission | `hil-submission` | `SUBMIT` | Binds exact response/provenance bytes and stages the canonical non-authorizing materialization request. |
| SV002 public observation | `sv002-public-observe` | `READ_OBSERVATION` | Uses event-ephemeral owner `.github#493` and canonical unavailable-receiver materialization. |
| Device Knowledge Vault | `device-kv` | `DISCOVER`, `REQUEST`, `COMMIT_CANDIDATE` | Attaches canonical request intent evidence without granting Site custody or write authority. |

Each connector is therefore one canonical build plus a named profile adjustment. Consumer-local intent, boundary, packet, and materialization constructors are not the source of truth.

## Lifecycle boundary

Source integration and deterministic tests do not establish a live receiver, transported packet, completed receipt chain, durable custody, TVC admission, review, publication, or release. Runtime observation remains separately authorized and must preserve authentic receipts from each sovereign lane.

## Validation contract

The credential-free workflow anonymously fetches the exact pull-request head and runs only preinstalled Python and Node.js:

```text
python3 scripts/check_generated_intr_connector.py
node --test tests/canonical-generated-intr.test.cjs
python3 scripts/check_session_work_claims.py
```

The existing HIL, evaluator, SV002, and claim validators remain additional integration checks. No package installation or runtime GitHub credential is required.
