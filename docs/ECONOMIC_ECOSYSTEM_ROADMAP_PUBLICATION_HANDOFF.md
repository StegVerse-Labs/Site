## Benchmark proof contract
An existing machine-owned Publisher projection should update the public benchmark file only after querying the exact canonical benchmark Task ID and corresponding exact state-transition evidence through the existing authorized Master Records binding. Every VERIFIED_COMPLETE benchmark requires:
1. An exact registered benchmark ID mapped to existing canonical task and COSV ownership (new task bindings must enter through canonical Task Registry, not invented locally by Site).
2. Authentic retained result evidence for the specific operational predicate. A source implementation, hosted CI, browser IndexedDB, proposed design, or synthetic fixture is not runtime success.
3. Canonical Master Records state=RECORDED, reconstruction_status=PASS and required_evidence_validation_status=PASS with exact receipt_sha256==reconstructed_receipt_sha256, plus any benchmark-specific constraints (for example genuine native installation).
4. If crossing organizational boundaries, the required authenticated external Interlock/InTr decision and exact scoped organization receipts.
5. Governed Publisher closure binding the release projection request to the verified source, exactly matching output content and intended public target. No direct submitter can mutate the public record under publication authority.
6. A retained authenticated publication result and public readback confirming that the Site received this version.

The public projection records only public-safe benchmark ID, status, verified_at, canonical public evidence reference and status snapshot timestamp. Unavailable or invalid proof is NOT_VERIFIED or UNKNOWN_NOT_AUTHENTICALLY_OBSERVED; never silently promote on CI success. When completed proof is later revoked, superseded, stale or invalidated, refresh the projection to a non-complete status. The public reader never computes completion from implementation percentage.
