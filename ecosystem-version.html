What the states mean

Built
The implementation exists in source. It does not mean validated, released, deployed, runtime-proven, or activated.
Validated
The declared checks passed for that implementation. It does not mean released or live.
Released
An exact version/tag/release boundary exists for the component. It does not mean deployed or activated.
Deployed
A concrete deployment event was observed. It does not prove the required runtime behavior.
Runtime-proven
The required live execution evidence was observed. It does not automatically grant activation.
Activated
Every declared activation gate for that component was satisfied with evidence.

Why this matters to users

A user should be able to answer three questions immediately: What can I use now? What is still being proven? and What exact component versions handled the request?

The first 13-component core governed lifecycle now has complete version-declaration and validator-installation coverage. The full repository universe is also enumerated. The remaining versioning work is handoff-backed classification, versioning newly admitted active components, executing and retaining validator evidence, and only assembling immutable aggregate releases where TV/TVC evidence supports them.
