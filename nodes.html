StegVerse Nodes

Choose where your StegVerse capability lives.

Every StegVerse Node participates under the same governance rules. Elevating a Node expands what that Node can observe, retain, execute, or serve; it does not grant greater governance authority.

Choose the boundary that matches how you want this Node to participate.

DEFAULT / INTRODUCTORY

Unselected Node

The default Node type before a persistent sovereignty boundary is selected.

KV boundary
No persistent KV operating boundary selected yet.
  • Explicit connection still required on a new device
  • Preserves bounded device continuity once established
  • Designed for introductory StegVerse capability

This is a bootstrap/default type, not a paid tier.

PRIVATE SOVEREIGNTY

Private Sovereign Node

Private user or organization sovereignty without requiring a resident StegOS runtime.

KV boundary
Your private KV remains under the owner-controlled Node boundary.
  • Private continuity and governed capabilities
  • No resident StegOS required
  • Selection does not grant KV access to StegVerse
ECOSYSTEM PARTICIPATION

Main Ecosystem Node

Shared ecosystem participation under common StegVerse services without implying private-KV custody.

KV boundary
Ecosystem services do not become custodian of your private KV.
  • Common ecosystem services
  • No resident StegOS required
  • Private data still requires explicit admitted sharing
PRIVATE + RESIDENT STEGOS

Private Sovereign StegOS Node

Private sovereignty plus an eligible resident StegOS environment for governed local or private workloads.

KV boundary
Private KV may be used by admitted resident workloads without ecosystem custody.
  • Resident StegOS predicates required
  • Selection records the request; it does not fabricate resident runtime
  • Additional capabilities remain independently admitted
ECOSYSTEM INFRASTRUCTURE

Ecosystem Sovereign StegOS Node

Ecosystem-governed resident StegOS infrastructure for common services and canonical public workloads.

KV boundary
Ecosystem state and evidence remain separate from private user KV unless explicitly shared and admitted.
  • Resident StegOS required
  • Ecosystem eligibility required
  • Not presented as a generally orderable consumer tier

Eligibility-restricted ecosystem infrastructure.

Node status describes capability and sovereignty—not rank. Commercial service entitlements may change available resolution or capability, but they do not change governance rules, evidence standards, KV ownership, or transition authority.
